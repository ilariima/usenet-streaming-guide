# beszel

Resource monitoring — CPU, memory, disk, network and per-container stats, with history and alerting. A hub with a web UI plus an agent that collects the data.

## compose.yaml

```yaml
services:
  beszel:
    image: henrygd/beszel:latest
    container_name: beszel
    restart: unless-stopped
    env_file:
      - .env
    environment:
      APP_URL: ${APP_URL}
    ports:
      - "${HUB_PORT}:8090"
    volumes:
      - ./beszel_data:/beszel_data
      - ./beszel_socket:/beszel_socket
    networks:
      - pangolin_frontend

  beszel-agent:
    image: henrygd/beszel-agent:latest
    container_name: beszel-agent
    restart: unless-stopped
    network_mode: host
    env_file:
      - .env
    volumes:
      - ./beszel_agent_data:/var/lib/beszel-agent
      - ./beszel_socket:/beszel_socket
      - /var/run/docker.sock:/var/run/docker.sock:ro
    environment:
      LISTEN: ${BESZEL_LISTEN}
      HUB_URL: ${BESZEL_HUB_URL}
      TOKEN: ${BESZEL_TOKEN}
      KEY: ${BESZEL_KEY}

networks:
  # Created by the Pangolin stack.
  pangolin_frontend:
    external: true
```

`pangolin_frontend` comes from the pangolin stack — deploy that first.

## .env

```dotenv
# ==============================================================================
# beszel — resource monitoring
# ------------------------------------------------------------------------------
# Copy to .env. Fill APP_URL now; the two agent values come from the hub's web
# UI after it is running, so you deploy once, collect them, then redeploy.
# ==============================================================================

# --- Hub ---
# The URL you reach the hub on. Must match the Pangolin resource you create.
APP_URL=https://beszel.example.com

# Host port the hub publishes.
HUB_PORT=8090

# --- Agent ---
# BOTH values are generated by the hub. Leave them as-is for the first deploy,
# then in the hub's web UI click "Add System" (top right). The dialog shows a
# token and a public key — paste them here and redeploy.
#
# In that same dialog, set Host / IP to the socket path below, not an address.
BESZEL_TOKEN=CHANGEME_FROM_HUB_ADD_SYSTEM
BESZEL_KEY=CHANGEME_FROM_HUB_ADD_SYSTEM

# Where the hub reaches the agent. The agent runs with network_mode: host, so
# localhost here is the host itself.
BESZEL_HUB_URL=http://localhost:8090

# The agent listens on a unix socket shared with the hub through a volume,
# rather than a TCP port.
BESZEL_LISTEN=/beszel_socket/beszel.sock
```

| Variable | What to put |
|---|---|
| `APP_URL` | `https://beszel.<your-domain>` — same hostname as the Pangolin resource below |
| `BESZEL_TOKEN` | From the hub, step 5 |
| `BESZEL_KEY` | From the hub, step 5 |

## Deploy

1. Create the stack in Dockhand and paste the compose.
2. Over SSH, create `.env` in the stack directory with the contents above and set `APP_URL`. Leave the two `CHANGEME` values for now.
3. Deploy the stack in Dockhand.
4. Create the Pangolin resource below, then open `https://beszel.<your-domain>` and create the admin account.
5. Click **Add System** (top right). In the dialog set **Host / IP** to `/beszel_socket/beszel.sock`, and copy the token and the public key (the `ssh-ed25519 …` line) into `.env`:

   ```dotenv
   BESZEL_TOKEN=<token from the dialog>
   BESZEL_KEY=ssh-ed25519 <key from the dialog>
   ```

   Leave the dialog open.
6. Redeploy the stack in Dockhand, then click **Add System** in the still-open dialog to finish.
